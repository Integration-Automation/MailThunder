## U-20260923-01 · 2026-09-23 · Importing no longer connects to Gmail or fails offline · #done #bugfix

- **Bug** (`progress.md` #6, was [UNVERIFIED]): confirmed by importing the package with `socket.create_connection` patched to raise `OSError` — `import je_mail_thunder` failed with `AttributeError: 'NoneType' object has no attribute 'later_init'` (`utils/executor/action_executor.py:32`). The SMTP and IMAP wrappers connected in their constructors, both were built at import, a failed connection left the instance as `None`, and `Executor()` read methods off it. With network available every import — the CLI running a `print` action included — first dialled smtp.gmail.com and imap.gmail.com.
- **Fix**: `smtp_instance` and `imap_instance` are `LazyInstance` proxies (`utils/lazy_instance/lazy_instance.py`) that build the real wrapper on first use and forward attribute reads, calls and `with` blocks to it. A connection failure now raises at that first use, where the executor records it as a failed action, and the next use retries. The executor registers `deferred(instance, "method")` callables so building it connects to nothing.
- **Compatibility**: `je_mail_thunder.smtp_instance.<anything>` works as before; the difference is `isinstance(smtp_instance, SMTPWrapper)` is now false (call `smtp_instance.get()` for the wrapper itself).
- **Tests**: `test/unit_test/test_lazy_instance.py` (6): importing with networking disabled and building an `Executor` makes zero connection attempts and exits 0 (the old code exits 1), build-on-first-read happens once, a failed build raises at use and is retried, `deferred` does not build until called, `with` is forwarded, and both package instances are lazy. Suite: 79 passed, and it no longer touches the network (≈3 s, was ≈10 s). flake8 at 120 columns clean.
- **Files**: `je_mail_thunder/utils/lazy_instance/{__init__,lazy_instance}.py`, `je_mail_thunder/smtp/smtp_wrapper.py`, `je_mail_thunder/imap/imap_wrapper.py`, `je_mail_thunder/utils/executor/action_executor.py`, `test/unit_test/test_lazy_instance.py`, `architecture.md` §2–§4, `progress.md`.

## U-20260923-07 · 2026-09-23 · The socket server no longer reads sys.argv · #change #socket #security

- **What** (`progress.md` #7): `start_mail_thunder_socket_server` replaced its `host`/`port` arguments with `sys.argv[1]`/`[2]` whenever the host process had one or two command-line arguments. Any program that embedded the server and was started as `prog.py <file>` bound to the file name as host (or, with a second argument, to whatever port it was given). Running `python -m pytest one_test.py` was enough. The server now binds exactly the arguments it is given. AutoControl's server had already dropped the same override; APITestka's and WebRunner's still have it.
- **Compatibility**: a script that relied on `python script.py <host> <port>` must pass them itself, e.g. `start_mail_thunder_socket_server(sys.argv[1], int(sys.argv[2]))`.
- **Docs**: `docs/source/docs/Eng/socket_server.rst` no longer documents the override; `API/utils_api.rst` says the server binds exactly what it is given.
- **Tests**: `test_command_line_arguments_do_not_rebind_the_server` (fails on the old code). Suite: 89 passed.

## U-20260925-01 · 2026-09-25 · Dependabot waits 7 days before proposing a new release · #ci #security #deps

- **What**: `.github/dependabot.yml` sets `cooldown: default-days: 7` on all 2 update blocks. Dependabot now proposes a version only after it has been public for 7 days, so a compromised release is more likely to be found and yanked before a PR exists.
