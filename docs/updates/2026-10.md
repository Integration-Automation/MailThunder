## U-20261008-03 · 2026-10-08 · Core mail API: `Mail` over a provider interface, with SMTP and IMAP providers · #done #api #providers #roadmap-2.0

- **What**: `progress.md` #12 (MailThunder 2.0 roadmap, P0 "New Core Mail API", "Provider interface" and "Backward compatibility layer"). Callers send and read mail without naming a protocol:
  - `je_mail_thunder/core/`:
    - `Mail(provider=None, auth=None, account=None, policy=None, providers=None)` with `send`, `create_draft`, `get_messages`, `get_message`, `delete_message`, `close`. Nothing connects until the first call; one lock per instance.
    - `MailMessage` (frozen): addresses given as text, comma lists or lists; `check_outgoing` refuses a message without a recipient or sender, an invalid address, and a subject or header that is not one line, so a value cannot inject a header. `rfc822` converts to and from `email.message.EmailMessage`.
    - `MailAccount` / `MailServers` / `default_account()`: the servers come from the OAuth2 presets, so `Mail()` and the module instances name the same hosts.
    - `actions`: the commands `MT_mail_send`, `MT_mail_create_draft`, `MT_mail_get_messages`, `MT_mail_get_message`, `MT_mail_delete_message`, `MT_mail_close` on the new module instance `mail_instance`, with JSON-ready arguments and results.
    - `compat`: `legacy_message` (the wrappers' arguments as a `MailMessage`) and `mail_from_wrappers` (a `Mail` on wrappers that are already logged in).
  - `je_mail_thunder/providers/`:
    - `MailProvider` with the roles `MailSender` and `MailStore`, so a backend implements only what it can do.
    - `SMTPProvider` and `IMAPProvider` on the existing wrappers (`WrapperProvider`: connect and log in on first use, 60 s socket timeout, a `NOOP` after 30 idle seconds, a new connection when the old one is dead).
    - IMAP: UIDs, `BODY.PEEK[]` (reading does not set `\Seen`), newest first and one message per step of the iterator, drafts into the folder flagged `\Drafts`, `UID EXPUNGE` with `UIDPLUS`, folder names in modified UTF-7, a non-ASCII search with `CHARSET UTF-8`.
    - `registry`: `register_provider(name, factory)`; `google` (alias `gmail`), `microsoft` and `smtp` are registered.
  - New exceptions: `MailThunderMessageException`, `MailThunderProviderException` with `MailThunderConnectionException` and `MailThunderSendException` (`refused`). A refused login is a `MailThunderAuthenticationException`.
- **Decisions**:

On Windows with Python 3.10 the clock stands still for about 16 ms, so messages stored in a quick loop got the same time and were ordered by the random part. `test_the_file_provider_reads_newest_first_and_deletes` failed once in the run that verified the commit after U-20261008-09.
- **Fix**: the provider remembers its last stamp and never reuses one (`max(last + 1, time.time_ns())`), so the names of one provider always sort in the order they were stored. Two processes writing the same folder in the same tick can still tie.
- **Result / numbers**: the two test files that store through the provider, run five times in a row on Python 3.10 on Windows: 31 passed each time.
- **Files**: `je_mail_thunder/providers/file.py`.
- **Open items**: none.

  - the script writes page content with `textContent` only, so a subject or sender that arrived by mail cannot run; a test fails if `innerHTML` appears in it;

## U-20261008-15 · 2026-10-08 · SMTP and IMAP verify the server's certificate; Studio serves loopback only; a lock file · #security #bugfix #tls #studio #sonarcloud

- **Why**: the SonarCloud quality gate of PR #46 failed on its security rating: five findings, read through the API. Looking into the one about certificate validation showed a real hole that predates the 2.0 work.
- **Bug** (`python:S4830`, reported on `SMTPStartTLSWrapper`): `SMTPWrapper` and `IMAPWrapper` did not verify who they reached.
  - `smtplib.SMTP_SSL` and `imaplib.IMAP4_SSL` use `ssl._create_stdlib_context()` when they are given no context, and that context has `verify_mode = CERT_NONE` and `check_hostname = False` (checked on Python 3.10 and 3.14). The wrappers gave them none.
  - Shown with a TLS server on `127.0.0.1` holding a self-signed certificate: before, both wrappers connected and would have sent the login; after, both refuse it with `ssl.SSLCertVerificationError`; with the certificate named in `SSL_CERT_FILE`, both connect. Run on Python 3.10 and 3.14 on Windows.
  - **Fix**: `utils/tls/tls_context.verified_client_context()` (`ssl.create_default_context(ssl.Purpose.SERVER_AUTH)`: certificate and host name verified, TLS 1.2 or newer), given to `SMTP_SSL`, to `starttls` and to `IMAP4_SSL`.
  - **Behaviour change**: a server with a self-signed certificate or a private certificate authority, which used to be accepted silently, is refused until a CA bundle holding its certificate is named in `SSL_CERT_FILE` / `SSL_CERT_DIR`. No switch turns the check off.
- **MailThunder Studio** (`pythonsecurity:S5131`, `python:S5332` twice):
  - the answer to an unknown address repeated the requested path; it no longer does (the answer was JSON with `nosniff`, so no script could run, but nothing from the request needs to come back);
  - Studio speaks plain HTTP and `--host` let it bind any address, which put the token and the mail on that network in the clear. **Decision**: it binds only `localhost` or a `127.x.x.x` address and raises `MailThunderStudioException` for any other; from another machine the port is forwarded through SSH. TLS inside Studio was the alternative; it would need a certificate to test with, and an SSH tunnel does the same job. `[::1]` is no longer an accepted `Host`, as the server never binds IPv6.
- **Lock file** (`text:S8565`): `pylock.toml` (PEP 751, written by `pip lock`) records what `[project] dependencies` resolve to, with hashes: `je-action-core 0.0.3`.
  - CI keeps installing the hash-locked `.github/requirements/test.txt`, which pins `je-action-core 0.0.1`, the floor of the range; the lock holds the newest version inside it, so raising the floor (PR #44) does not break it.
  - `test_dev_toml_parity.py` fails when the lock leaves the declared range or loses a hash.
- **Tests**: `test_wrapper_guards.py` (the context verifies; `SMTPWrapper` and `IMAPWrapper` are built with it), `test_studio.py` (five addresses that are refused, among them the all-interfaces ones; an unknown address is not echoed), `test_dev_toml_parity.py` (the lock).
