## U-20261001-06 · 2026-10-01 · OAuth2 (XOAUTH2) login for Google and Microsoft, and SMTP over STARTTLS · #done #security #oauth2 #L-8

- **What**: `progress.md` #5, workspace L-8. Google and Microsoft are retiring password logins for mail, so the SMTP and IMAP wrappers can now log in with OAuth2 (SASL `XOAUTH2`), using the standard library only:
  - **Settings**: `utils/oauth2/oauth2.py` has the `google` and `microsoft` presets (token URL, scope, SMTP and IMAP hosts) and `OAuth2Settings`.
    - It needs an access token, or a client ID plus a refresh token.
    - The token endpoint must be `https`, and the Microsoft tenant is checked before it goes into the URL.
    - Secrets stay out of `repr`.
  - **Tokens**: `refresh_access_token` posts `grant_type=refresh_token`. `OAuth2TokenCache` / `oauth2_token_cache` keeps tokens until a minute before they expire, and is thread-safe. Errors are `MailThunderOAuth2Exception`, naming the endpoint's error code, never a secret.
  - **Where the settings come from**: `credentials.resolve_oauth2_settings` reads the `"oauth2"` object of `mail_thunder_content.json`, else the `mail_thunder_oauth2_*` variables. Variables are looked up by name, because Windows keeps them upper-cased.
  - **Login**: `oauth2_login` on both wrappers. `try_to_login_with_env_or_content` uses OAuth2 when settings exist, else the password as before.
  - **STARTTLS**: Microsoft 365 accepts SMTP only on port 587. The new `SMTPStartTLSWrapper(SMTPClientMixin, smtplib.SMTP)` upgrades with a verifying `ssl.create_default_context()` before anything else is sent, and closes and raises when the server does not offer STARTTLS.
  - **Action files**: `smtp_instance` and `imap_instance` now connect to the servers of the provider the OAuth2 settings name (`default_smtp_client` / `default_imap_client`), so action files reach Microsoft too. Without OAuth2 settings they still connect to Gmail.
- **Before it**:
  - `f151842` pinned the login flow with tests.
  - `35a55fd` was the refactor: one shared credential lookup, and `SMTPWrapper`'s methods moved into `SMTPClientMixin`.
  - `1ce06c6` fixed a `mail_thunder_content.json` holding a JSON array, which crashed in `dict.update`; it is now logged and ignored.
- **Tests**: `test/unit_test/test_oauth2.py` has 36 tests:
  - settings, refresh, cache and HTTP errors;
  - where the settings come from;
  - `smtplib` and `imaplib` exchanging `XOAUTH2` with local fake servers, accepted and refused;
  - STARTTLS being refused, and the verifying context;

## U-20261008-01 · 2026-10-08 · Attachment policy: count, size and type checks before a message is sent · #feature #attachments #security #roadmap-2.0

- **What**: MailThunder 2.0 roadmap (`docs/MAILTHUNDER-2.0-ROADMAP.md`, PR #45), P0 "AttachmentPolicy". A new `je_mail_thunder/attachments/` package:
  - `Attachment`: a file to send (`path`, opened only when it is read) or one that arrived (`content`, kept out of the `repr`).
    - `save(directory)` writes it under `mime.safe_filename`, which drops directory parts of both separator styles, `..`, control characters, the characters Windows refuses and Windows device names. The target is checked again with `os.path.commonpath`.
  - `AttachmentPolicy`: `max_file_size`, `max_total_size`, `max_count`, `allowed_extensions`, `allowed_mime_types` (`image/*` works). `None` lifts a limit, and invalid settings are refused when the policy is built. `DEFAULT_ATTACHMENT_POLICY` is 25 MiB per attachment and per message.
  - `validate_attachments(attachments, policy)`: count → existence → size → extension → MIME type → total size. It logs the failure, then raises it.
  - Exceptions, all `MailThunderAttachmentException`: `AttachmentNotFound`, `AttachmentTooLarge`, `AttachmentTypeNotAllowed`, `AttachmentCountExceeded`, `TotalAttachmentSizeExceeded`, each with its numbers as attributes.
- **Limits, by design**: the type checks read the file name, not the content. The `SMTPWrapper` methods do not apply a policy; the core mail API (`progress.md` #12) will.
- **Docs**:
  - an "Attachment Policy" section in the three READMEs;
  - `docs/source/docs/{Eng,Zh}/attachment_policy.rst` and `docs/source/docs/API/core_api.rst` (new; attachments for now);
  - the exception pages (Eng and Zh), the API index, `docs/README.md`;
  - `architecture.md` §2 and §3.
